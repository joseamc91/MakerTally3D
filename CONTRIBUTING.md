# Contributing / Contribuciones

## English

- Use [Issues](https://github.com/joseamc91/MakerTally3D/issues) for reproducible bugs and proposals. Spanish and English are welcome. Discuss larger changes before opening a PR.
- Keep PRs focused and follow the existing Kotlin/Compose architecture and style. Code identifiers and technical comments are in English; UI resources must cover ES and EN.
- Preserve exact arithmetic, user data, accessibility and portrait/landscape. Do not introduce backend services, analytics or tracking without prior discussion.
- Run JVM tests, lint and Debug; run instrumented tests for relevant Android/storage/UI changes. See [development](docs/DEVELOPMENT.md).
- Review Light/Dark and ES/EN for UI changes; update documentation when public behavior changes.
- Never include credentials, signing files, local configuration, APK/AAB files or personal data. Report vulnerabilities privately under [SECURITY.md](SECURITY.md).

PRs are welcome, but acceptance depends on scope and maintainability. Contributions remain under the [Apache License 2.0](LICENSE). No separate corporate process or CLA is required here.

## Español

- Utiliza [Issues](https://github.com/joseamc91/MakerTally3D/issues) para errores reproducibles y propuestas, en español o inglés. Comenta cambios grandes antes de abrir una PR.
- Mantén cada PR acotada y respeta arquitectura y estilo Kotlin/Compose existentes. Identificadores y comentarios técnicos en inglés; recursos de interfaz en ES y EN.
- Conserva precisión, datos del usuario, accesibilidad y portrait/landscape. No introduzcas backend, analytics o tracking sin discusión previa.
- Ejecuta tests JVM, lint y Debug; instrumentados cuando se afecte Android, almacenamiento o UI. Consulta [desarrollo](docs/DEVELOPMENT.es.md).
- Revisa Claro/Oscuro y ES/EN en cambios de UI; actualiza documentación si cambia el comportamiento público.
- No incluyas credenciales, firma, configuración local, APK/AAB ni datos personales. Comunica vulnerabilidades por privado según [SECURITY.md](SECURITY.md).

Se aceptan PRs según alcance y mantenibilidad. Las contribuciones mantienen la [Apache License 2.0](LICENSE), sin proceso corporativo ni CLA adicional.
